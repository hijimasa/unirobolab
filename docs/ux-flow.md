# ライトユーザーの動線と、各フェーズで見せるもの・隠すもの(2026-09-16 草案)

前提: 対象は「URDF と ROS 2 のロボットは扱えるが、強化学習は専門でない」人。目的は
「自分のロボットに一つの動作を学習させて、実機で動かす」こと。強化学習の語彙(報酬、
ロールアウト、エントロピー、KL)は既定では出さず、ロボットの語彙(関節、目標、誤差、成功率、
周期、安全)で通す。専門家向けの層(契約 JSON、学習設定、TensorBoard、観測・行動の項)は
「詳細」の裏に置き、消さない。

## 原則

1. **物理量で語る。** 成功は「目標から 0.05 rad 以内」「目標地点から 0.15 m 以内」で示す。収益は出さない。
2. **時間で語る。** ステップ数ではなく経過時間と残り時間(早期終了の見込み)。
3. **一度に一つ。** 各フェーズの画面は一つの操作と一つの結果に絞る。
4. **失敗は次の一手に変換する。** 「成功率が上がらない」ではなく「目標範囲を狭めて再学習」ボタン。
5. **自動で決められるものは決める。** 契約の観測・行動、並列数、物理ステップ数、学習の予算は
   ロボットとタスクから導き、既定を表示だけする。

## フェーズと画面

### 1. ロボットを用意する
- 操作: URDF を選ぶ → スポーン → 関節を動かして確認(既存のエンティティパネル)。
- 見せる: 関節名と可動範囲、各関節の指令方式(位置 / 速度)、基体が動くロボットか。
- 隠す: 契約の観測ベクトル、スケール、履歴。**契約の草案はここで自動生成する**
  (関節順は URDF の順、ros2_control の指令インターフェースから mode、可動範囲から
  `safety.joint_limits`、速度制限から `max_joint_speed`)。
- 実装: `unirobolab draft-contract` と Contract タブの「Draft from URDF」(19 章)。関節順・可動範囲・指令方式・トピック名・固定/移動を URDF から読む。

### 2. 何をさせるか決める
- 操作: テンプレートから選ぶ。「関節を目標角へ動かす」「地点へ移動する」(将来: 「経路を追従する」)。
  目標の範囲、成功の許容誤差、1 回の制限時間をスライダで決める。
- 見せる: 目標の範囲を 3D で(到達範囲の円、関節の扇形)、成功条件を物理量で。
- 隠す: 報酬項の重み(テンプレートごとに固定)、PPO の設定、物理ステップ数。
- 実装: Task タブ(種類の自動判定、目標範囲・許容誤差・制限時間のスライダ、Save & train)。3D での範囲表示は未実装(20 章)。

### 3. 学習する
- 操作: 「学習を始める」一つ。停止と「やり直す(設定を変えて)」。
- 見せる: 成功率と誤差の推移(時間軸)、残り時間の見込み、動いているロボット 1 体の 3D 表示、
  「学習中の並列数(自動)」。
- 隠す: 収益、エントロピー、KL、クリップ率、n_steps、log_std。「詳細」で TensorBoard へ。
- 失敗 → 次の一手: 成功率が 0 のまま → 目標範囲を狭める / 制限時間を延ばす。
  誤差が振動 → 動作を滑らかにする(action_rate)。途中で悪化 → 学習率を下げる。
- 実装: 学習側が 1 秒ごとに `status.json` を書き、`unirobolab train-status` が「学習中 40% /
  成功率 62% (直近 200 回) / 誤差 0.041 / 目標 0.03 / 残り およそ 4 分 / 8 体並列」と
  次の一手 (成功 0 のまま → 目標範囲・制限時間、途中で悪化 → 学習率、下がり止まり → 許容誤差)
  に言い換える。Task タブに文と曲線 (誤差、成功率の移動平均) を出す。収益・KL などは
  「詳細 > Train」。3D 表示は Policy パネルのライブ実行で代替 (⑤で統合)。

### 4. 試す
- 操作: 目標を 3D 上で置く(クリック / スライダ)→ ロボットがその場で動く(Policy パネル)。
- 見せる: 目標までの誤差、到達までの時間、動作の軌跡。
- 隠す: 観測ベクトル、行動の生値(「詳細」で項ごとの推移)。
- 実装: Policy パネル (「Try the policy」) は Run で Task タブの契約と直近の学習出力を使う。
  地点到達なら「Pick in 3D」で地面をクリックすると目標マーカ (緑の円) を置いて送り、走った軌跡を
  青い線で描く。関節目標なら関節ごとのスライダで目標を動かす。状態は「誤差 0.08 m / 経過 4.0 s」の
  文で、生の JSON 行と契約・ONNX の入力は「詳細」のときだけ。

### 5. 配備前チェック(sim2sim)
- 操作: 「チェックを実行」一つ。シナリオは既定(目標数点 + 外乱 + 非常停止)。
- 見せる: 平易な言葉のチェックリスト。

  | 項目 | 平易な表現 | ok / NG の理由 |
  |---|---|---|
  | joints_present | 関節が見つかる | 見つからない関節名 |
  | rate | 決めた周期で動いている | 実測周期 |
  | obs_fresh | センサの値が新しい | 最悪の遅れ |
  | tracking | 目標に到達する | 目標ごとの誤差 |
  | (外乱) | 押されても戻る | 外乱後の誤差 |
  | estop | 非常停止が効く | 停止中の指令数 |

- 失敗 → 次の一手: 関節が見つからない → 関節名の対応表を出して選ばせる。到達しない →
  「観測にノイズを入れて再学習」「目標付近で留まる学習」(diffbot で実際に効いた 2 手)。
  値が古い → シミュレータのフレームレート設定。
- 隠す: status の JSON、report.json。「詳細」で開く。
- 実装: `unirobolab explain-report` が言い換えと次の一手を作り、Check タブ(ライト層)に表示。関節名の対応表は「近い名前の提案」までで、選ばせる UI は未実装。report.json の生の要約は「詳細」で表示。

### 6. 実機へ
- 操作: 「ROS 2 パッケージを作る」→ 接続先(トピック名、コントローラ名)のフォーム →
  安全設定(可動範囲、速度上限、非常停止トピック)を確認 → 手順書を出す。
- 見せる: 接続するトピック、実機で確認すべきこと(非常停止の配線、上限値、初回はランプイン)、
  起動コマンド。
- 隠す: onnxruntime、ノードの内部。
- 実装: Deploy タブ (ライト層)。名前空間、指令方式 (joint_states トピック / ros2_control)、
  コントローラ名、非常停止トピック、出力先のフォーム → 「Make ROS 2 package」で
  `unirobolab ros-set` → `gen` → `deploy-guide` を順に走らせ、パッケージに DEPLOY.md を置いて
  画面にも出す。手順書は接続するトピックの表、動かす前に確かめること (非常停止、上限値、鮮度、
  ランプイン、停止時動作)、起動コマンド、初回の見方。

## 専門家向けの層(残す)
「詳細」ボタンで表示を切り替える(既定は非表示)。契約 JSON の編集(Contract タブ)、学習設定、`import-isaaclab`、TensorBoard、観測・行動の
項ごとの推移、report.json、学習環境のスループット計測。ライトユーザー層は
これらを生成・呼び出すだけで、隠すのであって削らない。
