# ライトユーザーの動線 v2.1: フェーズ単位の画面設計(2026-09-16、レビュー反映)

前提は v1 と同じ(docs/ux-flow-v1-2026-09-16.md): 対象は「URDF と ROS 2 のロボットは扱えるが、
強化学習は専門でない」人。目的は「自分のロボットに一つの動作を学習させて、実機で動かす」。

v1 の実装(Task / Check / Deploy のタブ + 「詳細」)をチュートリアル(docs/tutorial.md)で通した結果、
動線として成立していなかった。この文書は、その問題の整理と、作り直しの設計。
v2 → v2.1 の変更(docs/reviews/2026-09-16-ux-v2-review.md と議論の反映):

- **カタログを持たない。** ② タスク は「開始条件と終了条件を 3D で定義する」画面にし、契約と
  学習設定はそこから生成される成果物にする(ユーザーは契約 JSON を探さないし開かない)。
- ① ロボット はテキストエディタ主役をやめ、URDF から読んだ構造の確認と実機の接続先の入力に絞る。
  契約 JSON と観測・行動の項リストは「詳細」へ。
- 接続先(名前空間、指令方式、トピック)は ① で決め、⑥ では変えない(⑤ で検証したものをそのまま配備)。
- ⑤ チェック は GUI のシミュレータ自身を被検体にして GUI で完結させる。
- プロジェクトに失効の規則を持つ(上流を変えたら下流は「要やり直し」)。
- 起動前の設定ファイル手書きを無くす(既定値と自動検出、初回セットアップ画面)。

## 1. 現状の問題(チュートリアルで分かったこと)

| # | 問題 | 何が起きるか |
|---|---|---|
| 1 | **今どのフェーズか分からない** | タブは押しても選択状態が見えない。Task / Check / Deploy の順序も、前後関係(学習が終わらないと Check は無意味)も画面に無い |
| 2 | **最初の一歩が専門家層にある** | 契約の草案(URDF → 契約)は「詳細 > Contract」にしか無く、ライトユーザーは初手で隠し扉を開けないと始められない |
| 3 | **画面がフェーズに合っていない** | 3D ビューが常に全画面で主役だが、契約を作る・チェック結果を読む・実機の接続先を書くフェーズでは 3D は不要。逆に「試す」では 3D が主役なのにパネルに隠れる |
| 4 | **パネルが 2 つに割れている** | 「試す」(Policy パネル)は別窓で、タブの流れの外にある |
| 5 | **入力がファイルパス** | URDF も契約もフルパスをタイプさせる。ファイル選択ダイアログ(StandaloneFileBrowser)は核に入っているのに使っていない |
| 6 | **状態が保存されない** | 再起動すると全部空欄。「昨日学習したロボットの続き」ができない |
| 7 | **言葉が混ざる** | ラベルは英語、状態文は日本語、キーは JSON の項目名(`joint_state_topic`)がそのまま |
| 8 | **前提条件が見えない** | 学習には learning_port、チェックには ROS 2(コンテナ)が要るが、押して初めて分かる |
| 9 | **起動前に設定ファイルを手書きする** | learning_port と Python のパスを JSON に書かないと学習ボタンが動かない。GUI に触る前の壁 |
| 10 | **契約が無くても操作できる** | 契約が空でもスライダと「Save & train」が押せる。上部の「ROS2 IP」バーがフェーズと無関係に常に見える |
| 11 | **見積もりの根拠が無い** | 「残り 21 分」が上限基準で実際は 12 分。許容誤差で学習時間が数倍変わることも分からない |
| 12 | **チェックが GUI で完結しない** | コンテナに入ってコマンドを打つ。既定のチェックに非常停止が入っていない |
| 13 | **⑥ の入力が ⑤ の検証を無効にする** | 実機の接続先を ⑥ で決めると契約の ros 節が書き換わり、⑤ で合格したものと別のパッケージになる |

## 2. 動線: 6 つのフェーズを一本の段取りにする

画面上部に**ステッパー**(段取り表示)を常に出す。現在のフェーズを強調し、済んだフェーズは ✓、
まだ進めないフェーズは薄く。フェーズは前提が満たされると解放される(契約が検証を通ると②、
学習結果があると④⑤、チェック合格で⑥…ただし⑥は警告付きで飛ばせる)。

```
 ① ロボット  →  ② タスク  →  ③ 学習  →  ④ 試す  →  ⑤ チェック  →  ⑥ 実機へ
 [✓ 済]        [● 今]        [ ]         [ ]          [ 要: 学習結果]   [ 要: チェック]
```

- 各フェーズは「その画面で決めること」が 1 つ。下部に「← 戻る」「次へ →」と、進めない理由。
- **プロジェクト**という単位を持つ: フォルダ 1 つ(URDF、契約、学習設定、runs/、sim2sim_out/、deploy/)。
  起動時は最後のプロジェクトを開き、ファイルの有無からフェーズを復元する(契約あり→②、
  runs/policy.onnx あり→④、report.json あり→⑤…)。
- 「詳細」は残すが、**フェーズごとの詳細**にする(①なら契約 JSON の全文と観測・行動の項、③なら
  収益・KL・学習設定 JSON)。全体の隠しタブは無くす。
- **失効の規則**: プロジェクトは各成果物の由来(元になったファイルのハッシュと時刻)を持つ。
  ① のロボットや接続先を変えたら ②〜⑥ の成果物は「要やり直し」、② のタスクを変えたら ③〜⑥、
  ③ で学習し直したら ④〜⑥、と下流に伝播し、ステッパーに「!」で出す。学習結果は runs/ に
  時刻付きで積み、「今の方策」はプロジェクトが指す 1 つ。
- **初回セットアップ**: 設定ファイルの手書きを無くす。learning_port は既定 10100 で常に有効、
  Python は同梱の環境(`scripts/setup_python.sh` の .venv)を自動検出し、無ければ画面から作れる。
  ROS 2 は「ある / コンテナで代用 / 無い」を検出して ⑤ に表示する。
- 核の「ROS2 IP」バーは ⑤ 以外では隠す。

## 3. 画面の骨格(共通レイアウト)

```
+------------------------------------------------------------------------------------+
| UniRoboLab   プロジェクト: servo_demo ▼        ① ロボット ✓  ② タスク ●  ③ 学習  ④ 試す  ⑤ チェック  ⑥ 実機へ |
+------------------------------------------------+-----------------------------------+
|                                                |                                   |
|   フェーズの主画面 (幅 60〜65 %)                |   3D プレビュー (幅 35〜40 %)        |
|   このフェーズで決めること 1 つ                  |   フェーズに応じて中身と大きさが変わる  |
|                                                |   (④ 試す では左右が入れ替わり 3D 主役) |
|                                                |                                   |
+------------------------------------------------+-----------------------------------+
| 状態行 (今何が起きているか、平易な 1 行)          [詳細 ▸]      [← 戻る]   [次へ →]     |
+------------------------------------------------------------------------------------+
```

- 3D ビューはフルスクリーンの背景ではなく**右側の枠**に描く(カメラの viewport rect を変える)。
  フェーズ①②では「プレビュー」、③では「学習中のロボット達」、④では主役、⑤⑥では小さく(または閉じる)。
- 状態行は常に 1 行。長い出力(ログ、JSON、レポート原文)は「詳細」の折り畳みへ。
- 言葉は一つに揃える(日本語フォントがあれば日本語、無ければ英語。ラベルも文も同じ言語)。
  JSON のキーは画面に出さない(`joint_state_topic` → 「JointState トピックで指令」)。

## 4. 各フェーズの画面

### ① ロボット(URDF を選ぶ、構造と接続先を確かめる)

契約はここで自動生成されるが、画面の主役は**構造の表**と**3D プレビュー**。契約 JSON は「詳細」。

```
+------------------------------------------------+-----------------------------------+
| URDF: [servo_demo.urdf            ] [選ぶ...]    |  3D: URDF を読むとスポーンして表示。   |
| ロボット名: [servo_demo   ]  基体: 固定 (自動判定) |  表の行を選ぶとその関節が光る。       |
|                                                |                                   |
| 関節              指令   可動範囲          上限速度 |                                   |
| ideal_joint       位置   -1.57 .. 1.57 rad  8 rad/s|                                   |
| cheap_joint       位置   -1.57 .. 1.57 rad  8 rad/s|                                   |
| センサ: IMU なし / オドメトリ なし (URDF から)      |                                   |
|                                                |                                   |
| 実機の接続先                                     |                                   |
|  名前空間 [servo_demo]  指令 ● JointState ○ ros2_control (コントローラ [          ]) |
|  非常停止 [/servo_demo/estop] (自動)                                                |
| 検証: ✓ 問題なし (観測 8、行動 2、25 Hz)                                              |
+------------------------------------------------+-----------------------------------+
| ロボットを読み込みました。関節名と接続先が実機と合っているか確かめてください   [次へ →]  |
```

- 「選ぶ...」は核の StandaloneFileBrowser。選んだ時点で草案(契約と、②の既定)を作り、3D にスポーンする。
- 表で直せるのは、ライトユーザーが実機に合わせて変える必要があるものだけ: 関節名、指令方式、
  可動範囲と上限(安全)、基体の種類、接続先。JSON のキーは出さない。
- 接続先はここで決め、⑥ では変えない(問題 13)。
- 「詳細」: 観測・行動の項リスト(1 項 1 行: 名前、元、対象関節、サイズ、スケール、履歴)と
  契約 JSON のエディタ。JSON が唯一の真実で、表とプレビューはその投影(双方向に同期)。
  専門家の入口「学習済み方策の取り込み (Isaac Lab)」「既存の契約を開く」もここ。

### ② タスク(開始条件と終了条件を 3D で定義する)

カタログから選ぶのではなく、**「どこから始まって、どうなれば成功か」を 3D 上で定義する**。
契約(観測・行動)と学習設定(報酬、終了、早期終了)はこの定義から生成する。

```
+------------------------------------------------+-----------------------------------+
| 開始条件                                        |                                   |
|  ロボットの姿勢: ● 固定 (今の姿勢)  ○ 範囲から抽選 |   3D: 開始のばらつき (半透明) と       |
|  ロボットの位置: [原点] 向き ±0°                  |   終了の領域 (緑) を描く。            |
| 終了条件 (成功)                                  |   ハンドルで範囲を動かせる。           |
|  [+ 条件を追加 ▼]  関節が目標角に / 基体が領域内 /  |   今の状態が条件を満たすと緑に点灯。    |
|                    物体が領域内 (将来)           |                                   |
|  ● 関節が目標角に: 目標は ±1.22 rad から抽選、     |                                   |
|    許容 0.05 rad                                |                                   |
| 1 回の制限時間 [===●====] 3.0 s   継続 [0.0] s   |                                   |
| 学習の目安: 約 3 分 (8 体並列、許容 0.05 rad;      |                                   |
|   0.03 rad にすると 10 分超)                      |                                   |
| 「詳細」: 生成された契約と学習設定、報酬の重み       |                                   |
+------------------------------------------------+-----------------------------------+
```

- **原始条件**(v1): 「関節が目標角に(目標を範囲から抽選、許容誤差)」「基体が領域内(領域は箱 / 球 /
  環、許容)」。開始側は「ばらつきの範囲」、終了側は「許容誤差つきの述語」で同じ部品を使う。
  将来: 「物体が領域内」「物体の高さ」「手先が点の近く」。
- 生成規則: 観測 = ロボットの関節・基体の状態 + 条件が参照するものの相対量(目標角、目標地点までの
  ベクトル)。行動 = 指令可能な関節(と台車)。報酬 = 各条件の満たし度の進捗 + 成功 + 動作の滑らかさ。
  終了 = 全条件を継続時間だけ満たす、または制限時間。早期終了 = 直近の成功率か誤差。
- 今の 2 テンプレートはこの枠のプリセット: 関節目標 = 「関節が目標角に」、地点到達 = 「基体が環の中」。
  プリセットは「例」として置くだけで、選ばなくてもよい。
- **学習時間の目安**を体数・許容誤差・範囲から出し、根拠を 1 行添える(問題 11)。
- 「次へ」で仕様(`task.json`)を保存し、契約と学習設定を生成して ③ へ。②で勝手に学習は始めない。
- 把持など接触を伴う作業は、条件は書けても学習が難しい。v1 では対象外と画面に明記する。

### ③ 学習

```
| [▶ 学習を始める]  [■ 止める]                                                  |  3D: 学習中のロボット達 |
| 学習中 21% ── 成功率 4% (直近 200 回) ── 誤差 0.179 (目標 0.03) ── 残り 約 3 分  |  (カメラは全体を収める) |
| [誤差 ▁▂▃▅▆▇  成功率 ▁▁▂▃ の曲線 (大きく)]                                     |                        |
| 次の一手: (成功率が 0 のままなら) 目標範囲を狭める → [②へ戻る]                    |                        |
| 「詳細」: 収益、KL、エントロピー、ログ、TensorBoard                              |                        |
```

- 学習が終わると「次へ(試す)」が解放され、状態行に結果を 1 行(「成功率 58%、誤差 0.030 rad」)。
- 前提条件チェックをボタンの前に出す: Python 環境が無い、シミュレータの学習サーバが動いていない、なら理由と直し方。
- 学習は runs/<時刻>/ に積み、終わったものを「今の方策」にする。過去の run は「詳細」で一覧・切替。
- 「次の一手」は提案値(狭めた範囲、延ばした時間)を入れた状態で ② へ飛ぶボタン。
- 残り時間は「上限まで」と「目標に達すれば」を分けて出す(問題 11)。

```

|  ✓ センサの値が新しい (最悪 36 ms)   ✓ 目標に到達する (3/3、最大誤差 0.065 rad)         |                    |
|  ✓ 数値が壊れていない              ✓ 非常停止が効く                                   |                    |
| NG のとき: 次の一手 → [①で関節名を直す] [②で許容誤差を広げる] ...(該当フェーズへのボタン) |                    |

```

- 「次の一手」は文ではなく**該当フェーズへ飛ぶボタン**にする(原則 4)。
- **実行モデル**: 被検体は GUI のシミュレータ自身(第 2 のシミュレータを起動しない)。手順は
  (a) パッケージ生成 → (b) ビルド → (c) ROS 2 経由でロボットをスポーン → (d) 方策ノード起動 → (e) 判定、
  を段階ごとに進捗表示する。ROS 2 は「ホストにある」「コンテナで代用(GUI から起動、ホストのシミュレータに
  接続)」「無い(チェック不可の理由を表示)」を検出する。既定のシナリオに非常停止を含める(問題 12)。
- ⑤ の検証対象(契約・方策のハッシュ)を記録し、⑥ はそれと同一であることを印で示す。

## 5. 実装方針

- 現在の LabPanel / PolicyPanel は捨てて、`LabWizard`(ステッパー + フェーズ画面の切替 + プロジェクト
  状態)に作り直す。外部処理(CLI 呼び出し、進捗の読み取り、ライブ実行器)は既存のまま流用する。
- 3D は `Camera.rect` でプレビュー枠に描き、フェーズごとに枠の大きさとカメラの狙い(ロボット全体 /
  目標範囲 / 学習中の全体)を変える。
- プロジェクト: `<dir>/unirobolab.project.json`(URDF、契約、学習設定、最後のフェーズ)。
  起動時に最後のプロジェクトを開く(`~/.unirobolab/recent`)。
- ファイル選択は核の StandaloneFileBrowser。
- 文言は一つの辞書(ja/en)に集め、JSON のキーは画面に出さない。
- 外部処理: 毎回 Python を起動せず、常駐の補助プロセス(stdin/stdout の JSON 行)にまとめる
  (検証、進捗、タスク仕様の生成、ライブ実行)。
- 進め方(レビューの優先順位): 共通骨格 + プロジェクト + ファイル選択 + 初回セットアップ →
  ② の条件定義(Python 側の仕様 → 契約・学習設定の生成を先に、GUI は関節目標と基体領域の 2 条件から)
  と ③ の学習時間の目安 → ① の最小版(選ぶ → 表 → 3D) → 接続先の ① 移動と ⑤ の GUI 完結 → ④ →
  ⑥ → ① の詳細(項リスト、JSON 同期)。各段でチュートリアルの該当節を撮り直して差し替える。
