# ライトユーザーの動線 v2: フェーズ単位の画面設計(2026-09-16、改訂)

前提は v1 と同じ(docs/ux-flow-v1-2026-09-16.md): 対象は「URDF と ROS 2 のロボットは扱えるが、
強化学習は専門でない」人。目的は「自分のロボットに一つの動作を学習させて、実機で動かす」。

v1 の実装(Task / Check / Deploy のタブ + 「詳細」)をチュートリアル(docs/tutorial.md)で通した結果、
動線として成立していなかった。この文書は、その問題の整理と、作り直しの設計。

## 1. 現状の問題(チュートリアルで分かったこと)

| # | 問題 | 何が起きるか |
|---|---|---|
| 1 | **今どのフェーズか分からない** | タブは押しても選択状態が見えない。Task / Check / Deploy の順序も、前後関係(学習が終わらないと Check は無意味)も画面に無い |
| 2 | **最初の一歩が専門家層にある** | 契約の草案(URDF → 契約)は「詳細 > Contract」にしか無く、ライトユーザーは初手で隠し扉を開けないと始められない |
| 3 | **画面がフェーズに合っていない** | 3D ビューが常に全画面で主役だが、契約を作る・チェック結果を読む・実機の接続先を書くフェーズでは 3D は不要。逆に「試す」では 3D が主役なのにパネルに隠れる |
| 4 | **パネルが 2 つに割れている** | 「試す」(Policy パネル)は別窓で、タブの流れの外にある |
| 5 | **入力がファイルパス** | URDF も契約もフルパスをタイプさせる。ファイル選択ダイアログ(StandaloneFileBrowser)は核に入っているのに使っていない |
| 6 | **状態が保存されない** | 再起動すると全部空欄。「昨日学習したロボットの続き」ができない |
| 7 | **言葉が混ざる** | ラベルは英語、状態文は日本語、キーは JSON の項目名(`joint_state_topic`)がそのまま |
| 8 | **前提条件が見えない** | 学習には learning_port、チェックには ROS 2(コンテナ)が要るが、押して初めて分かる |

## 2. 動線: 6 つのフェーズを一本の段取りにする

画面上部に**ステッパー**(段取り表示)を常に出す。現在のフェーズを強調し、済んだフェーズは ✓、
まだ進めないフェーズは薄く。フェーズは前提が満たされると解放される(契約が検証を通ると②、
学習結果があると④⑤、チェック合格で⑥…ただし⑥は警告付きで飛ばせる)。

```
 ① ロボット  →  ② タスク  →  ③ 学習  →  ④ 試す  →  ⑤ チェック  →  ⑥ 実機へ
 [✓ 済]        [● 今]        [ ]         [ ]          [ 要: 学習結果]   [ 要: チェック]
```

- 各フェーズは「その画面で決めること」が 1 つ。下部に「← 戻る」「次へ →」と、進めない理由。
- **プロジェクト**という単位を持つ: フォルダ 1 つ(URDF、契約、学習設定、runs/、sim2sim_out/、deploy/)。
  起動時は最後のプロジェクトを開き、ファイルの有無からフェーズを復元する(契約あり→②、
  runs/policy.onnx あり→④、report.json あり→⑤…)。
- 「詳細」は残すが、**フェーズごとの詳細**にする(①なら契約 JSON の全文と観測・行動の項、③なら
  収益・KL・学習設定 JSON)。全体の隠しタブは無くす。

## 3. 画面の骨格(共通レイアウト)

```
+------------------------------------------------------------------------------------+
| UniRoboLab   プロジェクト: servo_demo ▼        ① ロボット ✓  ② タスク ●  ③ 学習  ④ 試す  ⑤ チェック  ⑥ 実機へ |
+------------------------------------------------+-----------------------------------+
|                                                |                                   |
|   フェーズの主画面 (幅 60〜65 %)                |   3D プレビュー (幅 35〜40 %)        |
|   このフェーズで決めること 1 つ                  |   フェーズに応じて中身と大きさが変わる  |
|                                                |   (④ 試す では左右が入れ替わり 3D 主役) |
|                                                |                                   |
+------------------------------------------------+-----------------------------------+
| 状態行 (今何が起きているか、平易な 1 行)          [詳細 ▸]      [← 戻る]   [次へ →]     |
+------------------------------------------------------------------------------------+
```

- 3D ビューはフルスクリーンの背景ではなく**右側の枠**に描く(カメラの viewport rect を変える)。
  フェーズ①②では「プレビュー」、③では「学習中のロボット達」、④では主役、⑤⑥では小さく(または閉じる)。
- 状態行は常に 1 行。長い出力(ログ、JSON、レポート原文)は「詳細」の折り畳みへ。
- 言葉は一つに揃える(日本語フォントがあれば日本語、無ければ英語。ラベルも文も同じ言語)。
  JSON のキーは画面に出さない(`joint_state_topic` → 「JointState トピックで指令」)。

## 4. 各フェーズの画面

### ① ロボット(契約を作る)

ユーザーの指摘どおり、ここは**テキストエディタが主役、3D は補助のプレビュー**。

```
+------------------------------------------------+-----------------------------------+
| URDF: [servo_demo.urdf            ] [選ぶ...]    |  (URDF を読むとロボットをスポーンして  |
| ロボット名: [servo_demo   ]  基体: 固定 (自動判定)|   表示。関節を選ぶとその関節が光る)      |
|                                                |                                   |
| 契約 (自動生成。必要なら直す)                     |   関節 (2)                           |
| +--------------------------------------------+ |   ideal_joint  位置  -1.57..1.57 rad |
| | {                                          | |   cheap_joint  位置  -1.57..1.57 rad |
| |   "name": "servo_demo",                    | |                                   |
| |   "robot": { "joints": ["ideal_joint", ...  | |   周期 25 Hz                          |
| |   ...                                      | |   ROS: /servo_demo/joint_states →    |
| +--------------------------------------------+ |        /servo_demo/joint_command     |
| 検証: ✓ 問題なし (観測 8、行動 2)                 |                                   |
+------------------------------------------------+-----------------------------------+
| 契約と学習設定の草案を作りました。関節名を実機に合わせるなら左で直してください   [次へ →]  |
```

- 「選ぶ...」はファイルダイアログ(核の StandaloneFileBrowser)。URDF を選んだ時点で草案を作り、
  エディタに出し、3D にスポーンする(核の `TrySpawnRobotFromUrdf`)。
- エディタは編集のたびに `unirobolab show` で検証し、結果を 1 行で出す(行番号付きのエラー)。
- 右のプレビューは契約から導いた**要約**(関節と可動範囲、周期、トピック)で、契約の編集に追従する。
  JSON を読めない人はこの要約だけ見ればよい。
- 「詳細」: 観測・行動の項の一覧(名前、元、サイズ、スケール)。
- 将来: 関節名の対応表(実機の関節名 ↔ 契約)を表で編集する。

### ② タスク(何をさせるか)

```
| 種類: ● 関節を目標角へ動かす   ○ 地点へ移動する (基体が動くロボットのみ)         |  3D: 目標範囲の可視化    |
| 目標の範囲     [======●====]  ±1.22 rad                                        |  (関節: 扇形、地点: 輪)   |
| 成功とみなす誤差 [==●========]  0.05 rad                                        |                        |
| 1 回の制限時間  [===●=======]  2.0 s                                           |                        |
| 学習の目安: 約 3 分 (8 体並列、目標に達すれば早く終わる)                          |                        |
| 「詳細」: 報酬の重み、PPO の設定、学習設定 JSON                                    |                        |
```

- **学習時間の目安**を出す(許容誤差と範囲から経験則で。0.05 rad なら数分、0.03 rad なら 10 分超)。
  チュートリアルで一番の落とし穴だった。
- 「次へ」= 学習設定を保存して③へ(③の画面に「学習を始める」がある。②で勝手に始めない)。

### ③ 学習

```
| [▶ 学習を始める]  [■ 止める]                                                  |  3D: 学習中のロボット達 |
| 学習中 21% ── 成功率 4% (直近 200 回) ── 誤差 0.179 (目標 0.03) ── 残り 約 3 分  |  (カメラは全体を収める) |
| [誤差 ▁▂▃▅▆▇  成功率 ▁▁▂▃ の曲線 (大きく)]                                     |                        |
| 次の一手: (成功率が 0 のままなら) 目標範囲を狭める → [②へ戻る]                    |                        |
| 「詳細」: 収益、KL、エントロピー、ログ、TensorBoard                              |                        |
```

- 学習が終わると「次へ(試す)」が解放され、状態行に結果を 1 行(「成功率 58%、誤差 0.030 rad」)。
- 前提条件チェックをボタンの前に出す: learning_port が無い、Python が無い、なら理由と直し方。

### ④ 試す

3D が主役(左右入れ替え、または 3D を 65 %)。

```
+-----------------------------------+------------------------------------------------+
| 目標                                |                                                |
|  ideal_joint [====●====] 0.60 rad   |     3D (大): ロボット、目標マーカ、軌跡            |
|  cheap_joint [==●======] -0.60 rad  |                                                |
|  (地点到達なら「地面をクリックして目標」) |                                                |
| 誤差 0.038 rad  経過 18 s            |                                                |
| [▶ 動かす] [■ 止める]                |                                                |
+-----------------------------------+------------------------------------------------+
```

- 契約・ONNX の入力欄は無くす(プロジェクトから決まる)。「詳細」に観測・行動の生値。
- 実行中は時間倍率 1(実装済み)。

### ⑤ チェック(配備前)

```
| 前提: ROS 2 環境 ✓ コンテナ稼働中 / ✗ 無い → [コンテナを起動]  (sim2sim_command の設定)   |  3D: 小 (または閉) |
| [▶ チェックを実行]   最終: 2026-09-16 22:33  合格                                   |                    |
|  ✓ 関節が見つかる (2 関節)          ✓ 決めた周期で動いている (25 Hz)                  |                    |
|  ✓ センサの値が新しい (最悪 36 ms)   ✓ 目標に到達する (3/3、最大誤差 0.065 rad)         |                    |
|  ✓ 数値が壊れていない              ✓ 非常停止が効く                                   |                    |
| NG のとき: 次の一手 → [①で関節名を直す] [②で許容誤差を広げる] ...(該当フェーズへのボタン) |                    |
| 「詳細」: report.json の原文、シナリオの編集                                            |                    |
```

- 「次の一手」は文ではなく**該当フェーズへ飛ぶボタン**にする(原則 4)。
- ROS 2 が無い環境では、チェックを実行する場所(コンテナ)を GUI から起動できるようにする。

## 5. 実装方針

- 現在の LabPanel / PolicyPanel は捨てて、`LabWizard`(ステッパー + フェーズ画面の切替 + プロジェクト
  状態)に作り直す。外部処理(CLI 呼び出し、進捗の読み取り、ライブ実行器)は既存のまま流用する。
- 3D は `Camera.rect` でプレビュー枠に描き、フェーズごとに枠の大きさとカメラの狙い(ロボット全体 /
  目標範囲 / 学習中の全体)を変える。
- プロジェクト: `<dir>/unirobolab.project.json`(URDF、契約、学習設定、最後のフェーズ)。
  起動時に最後のプロジェクトを開く(`~/.unirobolab/recent`)。
- ファイル選択は核の StandaloneFileBrowser。
- 文言は一つの辞書(ja/en)に集め、JSON のキーは画面に出さない。
- 進め方: ステッパーと共通レイアウト → ① (エディタ + プレビュー + 要約) → ②③ → ④ → ⑤⑥ の順。
  各段でチュートリアルの該当節を撮り直して差し替える。
